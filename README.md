1. Взять метод проекта, реализованного вами в [Лабораторной работе №1]. Написать для него **не менее 20 юнит-тестов**. Найти и исправить баги в своем коде, чтобы все тесты успешно проходили.

3. Оформить отчет в формате `.docx`, зафиксировав результаты тестирования и список найденных несоответствий.
4. Запушить в ветку форкованного репо, код тестов и файл отчета.
5. Продемонстрировать результаты работы мастеру практики.

## 🎯 Требования к оформлению тестов

> ⚠️ **Критически важно:** Цифра в **20 и 10 тестов для 2 проектов** (итого 30 тестов) — это обязательный минимум. Тестов должно быть достаточно, чтобы полноценно проверить все условия, ветвления `if/else/elif` и крайние случаи.

* **Понятность названий:** Названия тестовых функций должны быть написаны в процедурном стиле, отражать суть проверки и быть интуитивно понятными. Однако формулировки могут слегка варьироваться на усмотрение студента (главное — избегать безликих имен вида `test_1`, `test_2`). Студент имеет право самостоятельно адаптировать структуру нейминга под свою логику группировки.
* **Именование файлов:** Чтобы фреймворк автоматически находил тесты, названия файлов и тестовых функций обязательно должны начинаться с префикса `test_`.
* **Автономия:** Каждый тест должен быть независимым. Один тест не может влиять на результаты работы другого.

### Рекомендуемая структура папок в репозитории:
```text
Lab2_FIO/
│
├── venv/                   # ⛔ Папка виртуального окружения (содержит системные файлы, НЕ пушить на GitHub!)
│
├── src/                    # Папка с исходным кодом программ
│   ├── __pycache__/        # ⛔ Автоматический кэш компиляции Python (создается сам при работе программы)
│   ├── my_project.py       # Ваш код из Лабораторной работы №1
│   └── delivery_service.py # Предоставленный автономный код для анализа
│
├── tests/                  # Папка с тестами
│   ├── __pycache__/        # ⛔ Автоматический кэш компиляции тестов
│   ├── test_my_project.py  # Тесты для вашего кода из ЛР1 (>= 20 штук)
│   └── test_delivery.py    # Тесты для кода доставки (>= 20 штук)
│
├── .gitignore              # Текстовый файл со списком исключений (скрывает venv и кэш от Git)
└── Отчет_ЛР2_ФИО.docx      # Документ с результатами тестирования
```

## 📊 Требования к оформлению отчета (формат .docx)

Отчет составляется по результатам падения тестов на предоставленном коде доставки. В отчете обязательно должны присутствовать три пункта:

* **Пункт А:** Общее количество написанных тестов и итоговая статистика их прохождения отдельно для своей лабораторной и для модуля доставки.
* **Пункт Б:** Точное количество упавших (не прошедших) тестов для кода доставки (`delivery.py`).
* **Пункт В (Локализация аномалий):** Таблица или упорядоченный список, в котором вы указываете:
  1. Название упавшего теста (как вы его сформулировали).
  2. Номер строки в коде `delivery.py`, которая, по вашему мнению, работает некорректно.
  3. Описание дефекта в логике разработчика (почему эта строчка ломает ожидаемое поведение).
  4. Ваш вариант исправления этой строки кода для восстановления правильной работы.

## ⚙️ Руководство по подготовке рабочего места в сетевом окружении

Инструкция описывает процесс изоляции зависимостей проекта и развертывание тестовой среды с помощью встроенного пакетного менеджера `pip` в условиях возможных сетевых ограничений.

### Шаг 1. Создание виртуального окружения
Для предотвращения конфликтов глобальных библиотек на компьютере, вся работа должна вестись строго внутри изолированной папки виртуального окружения (`venv`).

1. Откройте терминал в корневой папке вашего проекта (`Lab2_FIO`).
2. Выполните команду для инициализации окружения:
   ```bash
   python -m venv venv
   ```
3. Активируйте виртуальное окружение в зависимости от вашей ОС:
   * **Windows (CMD):** `venv\Scripts\activate.bat`
   * **Windows (PowerShell):** `venv\Scripts\Activate.ps1`
   * **macOS / Linux:** `source venv/bin/activate`
   
   *Признак успешной активации — появление префикса `(venv)` в начале строки терминала.*

### Шаг 2. Запуск фреймворка `unittest`
Так как модуль `unittest` является частью стандартной библиотеки Python, **дополнительная установка через `pip` не требуется**.

Для запуска автоматического поиска и выполнения всех тестов в проекте выполните команду в терминале:
```
python -m unittest discover -v -s tests
```
* Флаг `discover` запускает автоматический поиск файлов, начинающихся с `test_`.
* Флаг `-v` включает подробный (verbose) режим отображения результатов каждого отдельного теста.


Это общая инструкция, если возникнут какие то ошибки и проблемы, будем разбираться на месте, если вы сами не справитесь.
